# 电子兽装打版需求规格

整理日期：2026-10-26。对象为 FurryPattern CAD 0.8.0，源码基准为 `0bd71c8`。本轮只读核对代码，并按实际电子打版交付要求补充需求，见[修改说明](../../update/2026-10-26-pattern-production-docs.md)。本文记录制作目标、当前实现边界和验收要求；“已有实现”不等于本次验证通过。

阅读顺序：[版片与制作概念](../guides/concepts-and-workflow.md) → 本文 → [功能清单](../guides/feature-catalog.md) → [验收矩阵](acceptance-matrix.md)。参考依据见[19 张图片解读](../design/reference-image-analysis.md)和[外部项目研究](../design/reference-study.md)。

## 产品目标和使用者

软件服务于个人兽装制作者：将穿戴尺寸、填充外形、角色花纹和人工裁线整理为可编辑、可追溯、能按实际尺寸打印的版片。核心产物是一组有装配关系的二维纸样，包含制作所需的轮廓、孔洞、材料、数量、左右、毛向、接缝与对位信息。

版片不是模型上的三角面，也不是单独一张 UV 贴图。人体基体、填充外表面和角色外形承担不同作用；目标表面选错时，即使展平数值正确，纸样也可能不适合穿戴。制作流程仍需要制作者确定结构缝、细节做法、材料和实物试样。

| 使用角色 | 要完成的事 | 需要软件解释的结果 |
| --- | --- | --- |
| 制作者／打版者 | 标定、修图、选模型、贴花纹、裁切、修版、打印和试制 | 为什么跳过、哪里失真、哪条缝配对、哪些结果需重算 |
| 模型／模板整理者 | 准备毫米模型、部位和左右分类、测量环、拟合参数 | 输入测量与生成实测的差异、模板适用范围和失败原因 |
| 开发／验收维护者 | 维护契约、事务、几何和输出链，复现制作问题 | 输入版本、来源哈希、构建身份、实际输出与未验证范围 |

## 范围及输入输出

当前产品定位为 Windows 本地桌面软件。离线制作主线为：项目 → 原图与花纹库 → 模型 → 映射与审阅 → 裁线和展开候选 → 确认裁片 → 拼接检查 → 制版／输出。操作可以回退，但后续依赖必须重新判断。助手配置和外部本机连接为辅助功能，不是离线制作的前提。

| 数据 | 需求边界 |
| --- | --- |
| 角色设定图 | 保留整图；支持 PNG/JPEG/WebP、两点真实尺寸标定、手工修正、孔洞及制作方式。照片／画稿中不可见区域不能被当作已知事实 |
| 模型与模板 | 导入三角 OBJ/GLB 或生成内置／自定义模板；单位、部位、左右、形态用途明确；显示缩放不改尺寸 |
| 中间结果 | 保存来源区域、表面片段、审阅状态、裁线、候选指标及二维三维绑定；不能仅保存截图 |
| 正式制作结果 | 保存当前裁片、接缝、材料版本、排料、历史快照；支持 `.fpcad`、工作流／裁片交换及 SVG/PDF/PNG/DXF 输出 |
| 实物证据 | 100 mm 尺实测、接缝对位、材料方向、试缝外形与穿戴反馈；这些目前需在软件外记录，不能由拼接预览代替 |

本轮需求不把自动三维重建、任意照片精确量体、通用最少接缝、布料物理模拟、自动缝纫、云协作或商业服务列为已交付能力。这些方向保留在[后续规划](roadmap.md)，须另行定义输入、误差、资源和验收样本。

## 状态和优先级

- **已有实现**：找到当前界面入口与处理链，仍须按矩阵执行验收。
- **部分支持**：仅在特定输入或路径下成立，或接口存在而界面尚未接通。限制属于规格的一部分。
- **待规划**：缺少完整实现；不进入当前版本已交付清单。

P0 表示核心制作或数据正确性要求，P1 表示重要编辑／效率要求，P2 表示独立后续方向。优先级不表示发现了缺陷或承诺排期。以下 FR 编号与 F01–F31 对应；实现证据集中在功能清单，验收入口集中在矩阵，避免重复维护源码位置。

## 制作交付需求

以下要求来自电子打版的实际交付过程，不能仅由“算法成功”或“文件已导出”证明。操作与字段边界见[版片交付规格](../guides/pattern-delivery.md)，验收见矩阵 MC-01–08。已有功能可覆盖其中一部分，未结构化的信息当前需要手工标注；本轮不修改代码补齐它们。

| 需求 / 优先级 | 要求 | 当前能力与缺口 | 对应功能 |
| --- | --- | --- | --- |
| PR-01 / P0 制作对象 | 明确纸样属于人体基体、填充内胆、衬里或外覆毛皮，标出部位及连接对象 | 有模型与材料类别；缺少版片层次、层间对应及自动双层纸样。各套需分别命名并验证 | FR-10–13、22、24 |
| PR-02 / P0 版片身份 | 每份输出可追溯到项目版本、片、实例、左右及材料正反面 | 输出片号／实例、名称、修订等；左右／正反面需文字说明，模型左右分类不自动成为纸面标记 | FR-22、27 |
| PR-03 / P0 数量与方向 | 明确总份数、镜像份数、材料版本、毛向／布向及允许旋转 | 数量与镜像已有；单一有效箭头不代表双方向同时显示；仅填材料名不等于关联材料约束 | FR-22、24、26、27 |
| PR-04 / P0 线条用途 | 区分净样、裁剪线、缝份、孔洞、内部车线和折线；不把参考线裁成开口 | 净样／裁剪及孔洞支持；缺少通用内部工艺线对象，相关信息需另行说明 | FR-18、22–23、27 |
| PR-05 / P0 装配完整 | 每段应缝边明确对应实例、方向和对位点，保留开口明确列出 | 能检查已有接缝；无全部应缝边自动配对完整性保证，无实例级接缝与完整装配表输出 | FR-20–21、25、27–28 |
| PR-06 / P1 省道与开合 | 说明省尖／收合方向、拉链止点、连接件位置及相应留量 | 开放裁线和自由文字可辅助；没有完整省道、拉链、门襟和开合件专用对象 | FR-18、22–23、28 |
| PR-07 / P0 片组可制作 | 保留材料与锁定缝，在质量约束内减少非必要碎片；整组应可识别和装配 | 有补缝／合并与检查；不保证全局最少片数。真实小材料岛不能因面积小被删除 | FR-19、21–27 |
| PR-08 / P0 交付可复核 | 最终文件独立回读，检查比例与完整性，再按指定材料／部位试样 | 软件输出已有；真实打印和实物仍需对应记录，制作流备注不会自动印在纸上 | FR-27–28、NFR-01、NFR-09 |

PR-01–08 是当前制作主线的需求，不与账号、云服务或插件建设绑定。PR-06 的通用工艺编辑器可后续建设，但当前交付仍应以人工说明补足必要工艺信息。

| NFR-06 / P0 响应和预算 | 耗时计算不阻塞编辑主线；有任务进度／取消／超时与可理解失败。大输入应明确拒绝，不能无界耗尽资源 | 现有阈值是防护条件，不是性能达标证明；需记录硬件、输入、队列等待、耗时、峰值内存和取消延迟 |
| NFR-07 / P1 操作可恢复 | 草稿／正式状态可辨，切页、失败、重启和关闭的处理可解释；简单模式提供制作主线，高级工具不改变基础单位 | 未提交交互草稿不承诺跨重启恢复；可恢复数据以实际提交和恢复点为准 |
| NFR-08 / P0 文件兼容 | 导入执行大小、路径、契约和资源完整性检查；旧版本要么明确迁移成功，要么报错且保留原文件 | 当前项目契约 schemaVersion 2，保留 1 → 2 入口；不承诺任意未来或第三方项目兼容 |
| NFR-09 / P0 可验证交付 | 每项验收关联输入、源码／构建、命令、输出和限制；失败／取消保留证据 | 自动检查、桌面操作、输出回读和实物试样分别记录，不能互相替代 |

继续保持现有 Tauri、IPC 来源、文件和本机助手权限边界。本轮按用户范围只整理功能和实现表现验收，不增加安全测试工作包。

## 数值门槛：实现值与制作目标分开

[算法链](../design/algorithm-pipeline.md)和[平衡重试](../design/arap-balanced-retry.md)记录公式及适用路径。下表是当前源码中的检查，不能推导为所有输入都能达到的质量保证。

| 当前值 | 含义和限制 |
| --- | --- |
| 网格顶点／面分别最多 200,000；展开最多 50,000 面 | 对应入口／任务预算，达到上限不代表能在固定时间内完成 |
| 普通表面任务默认 120 s；裁切预览按工作量计算 60–900 s | 预览预算与边界点数、特定自动材料裁切的面数有关；不是固定 60 s，更不是实测耗时 |
| 设计路径每面组合失真上限 0.15、面积误差上限 0.15、边长误差上限 0.10 | 按最大值检查硬上限；面积加权均值另作报告，不能掩盖局部坏片，还需看分位数、重叠及片级结果 |
| 接缝相对误差 0.0005、绝对误差 0.25 mm | 对应自动设计质量门槛；人工接缝另按自身公差／吃量检查，不能混用 |
| 面级失真 P95 0.05 警告 | 是审阅提示，不是“95% 制作成功率” |

真实制作尚需确定：不同材料和部位能接受的局部伸缩、最小可缝宽度、尖角与小岛处理、毛向偏差、曲线段对位、填充及穿着活动余量。这些目标须用试样形成约定，暂不凭截图填写统一数值。结构缝数量／位置也应由装配需求和失真共同评估，不能只追求少片。
