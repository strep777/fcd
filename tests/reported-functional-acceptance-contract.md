# Reported workflow acceptance contract

This contract covers the reported extraction, garment-model, placement, cutting, whole-reference-sheet and persistence defects. Results are recorded under `test-results/2026-10-26-reference-sheet/`. Earlier interrupted and failed runs remain separate evidence; a later pass never replaces their logs. Tests use isolated libraries under `.local/tests/`, never `.local/workspace/`.

## Functional requirements

| Area | Required observable result |
| --- | --- |
| Whole reference sheet | Import one original-resolution sheet without front/back source controls. Identify separated figures and propose physical placement for review. Swapping complete figures preserves each source pixel, material owner and original coordinates after reversing the move. Legacy projects retain their data. |
| Extraction | Preserve real corners, narrow tips, holes and colour regions. The analytic import gates remain 1.5 px position error and 20 degrees tangent error, including actual JPEG compression. Tail and thigh material landmarks have distinct owners. |
| Eye details | Pupils, highlights and iris details remain editable print/decal details. They do not become extra sewn cloth pieces. Independent anatomical eye windows define the acceptance, not a fixed number of colour components. |
| Garment body | The padded clothing shell has one connected body and five real openings: collar, two cuffs and two hems. It contains no head, hands or feet. DTD and saved legacy models remain separate and readable. |
| Placement | Real card drag/drop and automatic placement preserve full geometry and holes. Missing or ambiguous anatomy produces an explicit reason. Proposed placements remain unreviewed until confirmed. Cancellation or failure leaves the prior state intact. |
| Cutting | Actual UI calculation produces 10–50 economical garment pieces on the reported input. Internal mesh edges are not automatic seams. All material domains and locked cuts remain; a sub-100 mm² piece is accepted only when an independent source-support oracle proves it is a complete real material island. |
| Physical quality | Keep area error ≤0.15, edge error ≤0.10, combined distortion ≤0.15, seam error ≤0.25 mm and local paired seam ratio ≤0.0005. Audit complete physical coverage, UV overlap, boundary validity and original-model correspondence independently. |
| Locked cuts | Check the actual two-sided cut, edge lengths, simple boundary loops and connected vertex fans. Preserving only cut metadata is insufficient. Unrelated temporary seams may merge. |
| Manufacturing | Simple mode shows pattern preview; material, seam and nesting controls belong to advanced mode. Accept the real candidate, export SVG/DXF/PDF at millimetre scale with a 100 mm ruler, then save, reopen and restart the process. |
| Persistence and responsiveness | Large geometry resources are shared without weakening hash checks. Rename, undo, redo, recovery, request replay and shared-session deletion preserve exact geometry, stale dependencies, review state and atomic failure behavior. |

## Final acceptance status

The recorded functional baseline, complete affected-file reruns, all 68 desktop suites and the latest actual UI cut pass. `desktop-final-leg-side/manufacturing/report.json` records eight passing downstream stages on that same 36-piece candidate: acceptance/history, simple preview, SVG/DXF millimetre output, actual A4 PDF with a 100 mm ruler on all 60 pages of the selected largest-bounds piece, archive save/reopen, undo/redo, and a new native process with restored assembly. Both native test processes closed. These results verify the reported workflows, not every possible drawing or a global minimum-cut proof.

Remaining limits: the large final cut takes about 11 minutes and is close to its unchanged deadline; large-project persistence still takes seconds. Automatic placement remains a reviewable hypothesis and exposes missing parts or unknown classification. Numerical near-zero source residues and incomplete visual coverage remain explicit rather than silently discarded.
