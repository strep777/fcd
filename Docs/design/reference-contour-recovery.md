# Reference contour recovery audit

The extractor recovers geometry from the original-resolution pixels and their classified material boundaries. It does not beautify outlines or impose smoothness. Straight spans remain lines. A cubic is accepted only when the original span cannot be explained by a digital straight segment and a geometric least-squares fit remains within the original boundary envelope. A separately verified straight-sided source polygon can recover the intersection of blurred sides beyond that raster envelope, as described below.

## Primary algorithm references

- Peter Selinger, [Potrace: a polygon-based tracing algorithm](https://www.mathstat.dal.ca/~selinger/potrace/potrace.pdf), 2003, sections 2.2.1–2.2.4: digital straight paths and polygon reconstruction. The aesthetic curve smoothing stage is intentionally excluded.
- DGtal, [Digital straight segment recognition](https://www.dgtal.org/doc/1.4/moduleArithDSSReco.html), and [StabbingLineComputer](https://dgtal-team.github.io/doc-nightly/classDGtal_1_1StabbingLineComputer.html): recover lines from digital boundary evidence instead of treating alternating raster edges as physical corners.

This implementation uses bounded numerical strip recognition and data fitting; it does not claim to be a complete implementation of either reference or a universally optimal tracer.

## Contract

The 0.8-pixel caller argument remains compatible with the old API. The native pixel grid is inferred from traced raster edges, including rotated/calibrated inputs. The recognition strip is at most 1.8 native pixels wide. This is distinct from the final, conservative bidirectional boundary-error bound of 1.05 native pixels, including curve flattening and unsampled-distance margins.

Every reconstructed ring must retain winding, its corresponding hole, containment and nonintersection. The default raster-area allowance is 3% (with a one-pixel-square floor). Small holes below 16 native pixel squares stay exact. A compact, independently measured light island can additionally use the half-pixel boundary-coverage area allowance described below; this does not relax the 1.05-pixel distance or topology checks. Native contact bevels and very acute tips remain protected. Other corners are reconstructed from supporting lines inside the pixel uncertainty, without averaging anchors or enforcing C1 continuity.

A narrow, nearly parallel straight strip can be ill-conditioned after an image-edge truncation. When independent intercepts violate the area bound, the recovery can apply a minimal one-dimensional thickness adjustment to reach the existing 3% measurement constraint. It retains edge directions and native clipping coordinates, caps the total width adjustment at half a native pixel, and still requires the full topology and 1.05-pixel boundary checks. It does not round edges or optimize appearance.

The fitter first keeps the compact outline and restores original holes if a hole fit fails. It can retain supporting corner anchors locally before considering the exact raster boundary. An irreducible outer contour above 2000 editable nodes reports RESOURCE_LIMIT rather than silently saving an invalid source.

On a straight-only candidate, a clipped raster corner or acute tip can lie off the supporting line. Instead of repeatedly subdividing the entire straight span into stairs, the fitter retains its endpoints and projects interior source samples onto that measured line, with short connecting segments at the ends. This candidate still passes the same bidirectional boundary, area and topology checks. It does not impose tangent continuity or replace measured arcs with straight segments.

## Implementation and checks

The implementation lives in packages/reference/recover-contour.ts, image-contour.ts, contour-topology.ts and shared-contour.ts. Source-tip measurements use image-line-corners.ts and image-gaussian-coverage.ts; the image-tip-* modules handle partial windows, exact splicing, source-distance eligibility, joint endpoints and observed-pixel caching. Focused tests in tests/integration/ cover digital straight spans, curves, holes, touching materials and real source contours. Test outputs are generated under test-results/; they are not maintained in this document.

The complete shared boundary network is recovered in a canonical source-pixel frame, then transformed back to millimetres. Translation, rotation and scale are normalized before intersection and sampling work; only floating-point transform noise is rounded. Contact and sampling budgets therefore do not change when the same image is calibrated at a different physical size or angle. Each shared chain is fitted once and traversed in reverse by its other material owner.

Fine intersection checks include nonadjacent segments within the same chain as well as different chains. When a fit crosses at a narrow gap, only the original measured edges near the collision are protected. The remaining intervals are refitted between fixed contact endpoints. Reverting an entire long chain would reintroduce stairs far away from the collision. Winding, hole containment, area and boundary-error checks still apply after every repair.

`tests/integration/contour-default-real-edge.test.ts` exercises the default dual-image extraction route on the user's fixed source fixture, checks three straight crown spans and the complete network across calibration sizes and rotations. `reference-native-validity.test.ts` also sends resized real-image results through the native validator; its 1.2-scale case covers a small self-crossing within one shared chain. `tests/contour-image-boundary-audit.mjs` compares saved output with source colour transitions as a diagnostic. JPEG blur and painted shadows mean that a colour-gradient peak is not a ground-truth boundary; this diagnostic does not replace the explicit geometry contracts.

Advanced colour selection uses the same source-constrained recovery through apps/desktop/main/reference-contour-fit.ts. Its custom millimetre tolerance is an additional bound, not permission to smooth straight edges. The candidate must satisfy both that tolerance and the native-pixel bound. Original hole polygons remain exact and are checked against the recovered exterior. If the tolerance cannot be met or conservative sampling exceeds its resource budget, the original geometry is returned with an explicit fallback report. The generic polygon Bézier fitter remains available separately for non-raster callers.

The final editable-node contract is checked after recovery, so a high-resolution raster with more than 2000 boundary samples can produce a valid compact selection. A fallback that still exceeds the editable-node contract is rejected; the sampling budget never overrides the saved-project limits.

The custom fit derives its pixel size from the candidate raster dimensions and the reference calibration. Legacy proxy-based clustering therefore uses the proxy's pixel size; it does not gain original-resolution edge evidence merely by fitting a contour.

Run `node tests/contour-edge-evidence.mjs` to generate an algorithm comparison against the current Git HEAD in test-results/edge-fidelity. It includes the baseline commit and measured boundary-error bounds; its image is generated geometry evidence, not an application screenshot.

## Original-image transition evidence

Default native-resolution illustration extraction also measures the original RGB transition. It first resamples collapsed raster runs at one-pixel spatial intervals, estimates a local normal, and locates a unique half-contrast crossing between the local material plateaux. Chromatic normalization reduces brightness/shadow bias; low-contrast or ambiguous samples do not invent an edge. Supported samples are fitted with measured lines or independent cubics, without a smoothing, tangent-continuity or curvature penalty.

The measured-line strip allows one native pixel of normal variation on spans longer than 28 pixels, while short spans retain the tighter 0.6-pixel limit. This accommodates hard raster diagonal sampling without promoting every stair into a corner. Image cusp detection uses six samples on each side and requires four pixels of support. Measured cubics allow at most 0.65 pixels of sample residual; the final 1.05-pixel bidirectional raster envelope, area and topology checks remain mandatory.

An independent closed image boundary is split at persistent measured corners when available. An arbitrary tracing start just before a corner would hide that corner from the two-sided test and introduce a short false bend. Smooth loops retain the farthest-point split. Closed boundaries with fixed shared contacts do not enter this image-fitting route, so their junctions stay fixed.

An arc–short line–arc decomposition can introduce a false cusp when a greedy knot falls inside a raster stair. For chains up to 2048 samples, recovery can reselect a nearby original knot using independent fits on both sides. It protects genuine corners and contact bevels, accepts no more than 0.05 pixels of additional measured error, and still checks the complete chain. A maximum of 32 knot candidates and eight full refits bounds this optional search. Budget exhaustion retains the original valid fit; no tangent or join-angle objective is used.

Before contour fitting, weak pigment cleanup checks normalized source RGB on both sides of a candidate region. A quiet interior and a consistent, abrupt material step preserve a pale painted region even when its saturation is low. Diffuse warm illumination remains eligible for shadow suppression. Normalized chroma cannot distinguish white from black, so white insets in dark material additionally use strongly separated luminance plateaux. The ordinary noise threshold remains 16 pixels; a bright detail of at least four pixels can survive when dark-material boundary contacts independently support it. Late one-to-three-pixel foreground fragments are assigned to the closest adjacent material in source RGB rather than silently creating holes. Actual background gaps are not filled.

`source-blended-materials.ts` checks whether an apparent third hue is an antialiased mixture of two established chromatic pigments. Each qualifying profile must contain seventeen opaque foreground samples, distinct three-sample endpoint plateaux, adequate RGB contrast and a monotone mixture with a small orthogonal colour residual. A separate white plateau, independent third colour, alpha gap or dark material rejects this interpretation. The helper proposes changes from a fixed label snapshot and commits them together; exceeding the 200,000 eligible-profile budget leaves all labels unchanged. This removes supported transition fragments without changing the source image or treating every intermediate hue as a new fabric.

Pink-instance separator validation runs inside each existing instance's pixel bounds. Raster order, source brightness, ink and strong-band samples are retained, and indices are mapped back to the original image before returning. Pixels outside the instance cannot participate in its flood or supply same-owner separator evidence. Family masks for the earlier cleanup passes are populated from the already verified foreground list, avoiding repeated scans of empty image space. These changes reduce redundant work without changing classification thresholds, candidate order or source ownership.

`image-small-details.ts` re-evaluates antialiasing coverage only for compact, opaque light regions with one dark surrounding owner. It retains connected light cores and a connected local complement. Pixel transfers are accumulated and appended once per receiving material, so many glints do not repeatedly copy a large background mask. Translucent pixels, several surrounding materials, insufficient contrast or ambiguous topology keep the prior classification.

`image-compact-contour.ts` traces the half-coverage isophote directly in the original pixel-centre RGB field for qualifying small closed islands. Ambiguous marching cells, multiple compatible loops or missing opaque plateaux reject the proposal. Source gradients supply tangent observations to a bounded least-squares fit; they are not a post-fit smoothing operation. The sample residual is at most 0.15 native pixels. An exactly subdivided cubic supplies the minimum three editable nodes when necessary without changing the path. This route may use a source area allowance of half a native pixel times the original ring perimeter. That evidence is valid only while the complete ring retains its one closed source-fitted chain; any fallback removes the allowance. Winding, holes, intersections and the bidirectional 1.05-pixel bound still apply to both owners.

Local material ownership refinement uses nearby interior RGB observations rather than a global hue threshold alone. It preserves foreground membership and checks simple-point connectivity for both affected owners before each move. A bounded colour-ray model handles highlights between warm pigments; neutral pairs and dark material retain separate evidence rules. Chromatic cast shadows cannot become white solely because a bright local mean is farther away. Dark reflections require independent dark support on opposing sides; one-ended drawn strokes do not become new black fabric. Blue reflections require a compact blue interior next to independently established dark material and continuous RGB evidence. Multiscale flat colour steps, other materials, ink and flat neutral plateaux stop propagation.

Ordinary shared-chain fitting keeps its junction coordinates fixed. Straight support is estimated from the measured interior, excluding the quantized endcaps; short endpoint connectors preserve the network rather than bowing the whole line. A separate source-supported junction preparation can move a common endpoint before fitting, as described below. If image evidence fails validation, the shared chain restores its constrained raster reconstruction before considering any exact pixel fallback. The diagnostic `imageSupportedChains` counts image fits retained after validation.

An invalid owner may contain several independently measured chains. Before reverting all of them, network validation tries at most sixteen individual chain reversions. A trial must repair the failed owner and preserve every previously valid neighbouring owner, using each owner's correct source baseline after the reversion. Neighbour validity is recorded before withdrawing source evidence, so validation order cannot silently make an invalidated neighbour exempt from the check. If no individual reversion repairs the owner, the conservative full incident-chain fallback remains available. `shared-contour-local-fallback.test.ts` covers both owner orders, shared holes, evidence withdrawal, translated/rotated calibrations and unchanged inputs.

Independent tests sample analytic RGB shapes and compare final geometry with their known boundaries. They also inspect proposals before network validation, so a downstream fallback cannot hide an unreliable image proposal. These tests cover lines, curved bands, circles, acute tips, thin rings, shared holes, calibration scale and rotation. The method is informed by [subpixel Canny/Devernay edge localization](https://www.ipol.im/pub/art/2017/216/) and [LSD line support](https://www.ipol.im/pub/art/2012/gjmr-lsd/); this is an original implementation, not either reference algorithm. Ambiguous source pixels do not determine a unique physical edge, and the implementation does not claim universal optimality.

The fixed complex multicolour stress fixtures also compare the result to intended geometry before Gaussian blur. The requested acceptance permits reconstructing an original tip from reliable flanking straight sides even beyond the visible blurred edge. `image-line-corners.ts` proposes flank intersections in native pixels, then tests a Gaussian-blurred two-material wedge against the original opaque RGB samples. A planar illumination term accounts for local lighting without smoothing the image or the recovered coordinates. The candidate competes with truncated flat and rounded end models using the same source neighbourhood. Physical colour bounds, contrast, source residual and flank support must justify the sharp model; a better supported flat or rounded end rejects extrapolation. Missing alpha and incompatible material transitions also reject it. An entire closed polygon is eligible only when all its corners and intervening straight edges are supported; a cropped boundary remains on the image border.

When only some corners are supported, `image-tip-partial.ts` selects nonoverlapping windows inside their measured source patches. `image-tip-splice.ts` replaces those intervals with the two flanks and their recovered intersection. It retains the other straight edges and round ends. A retained cubic portion is an exact subcurve of the original fit, including its control points; no whole-outline refit or tangent objective is applied. Open paths and windows crossing a closed tracing start use the same ordered path coordinates. The complete replacement must still pass its source-distance check and, for a closed path, the area and topology checks. A failed measured-base splice can try the constrained raster fit before retaining the ordinary recovery route.

`image-tip-source-tube.ts` allows an already measured base only when its entire path remains within the original raw-distance contract. It flattens cubics at 0.01 native pixels and checks both paths at intervals no longer than 0.08 pixels. Sample distances must be at most one pixel. The unsampled distance bound adds at most 0.04 pixels; flattening adds at most 0.01, retaining the 1.05-pixel envelope. Nonfinite inputs and exhausted work budgets decline the source base. Each input has at most 2048 nodes and 512 curves; flattened interval nodes are capped at 4096, with one final endpoint for an open path. Segment-pair work is capped at one million and distance checks at ten million per direction.

For a verified polygon or partial-tip proposal, both owners use the same source-certified boundary as their validation baseline. Only certified windows replace the raw boundary; other intervals retain the raw baseline. Winding, hole containment, nonintersection and shared ownership checks still apply. Restoring an image fit to its raster reconstruction revokes that alternate baseline immediately. This source boundary does not authorize the compact-island area allowance on unrelated chains.

`image-tip-junctions.ts` prepares a shared endpoint from the measured carriers of three or four incident branches. Every carrier must have source support, their intersection must agree within the residual bound, and a clipped carrier keeps the endpoint on its image border. All incident branches receive the same endpoint. Preparation precedes chain fitting, and the revised graph is reconstructed and validated before use. Invalid or failed preparation falls back to the unchanged graph; recursive validation does not prepare it a second time. The callback retains its receiver and receives nodes, holes and cubic controls in consistent world units. Returned chain count, finite coordinates and total point budget are checked before remapping. Junction preparation limits images to 4096 squared pixels, 2048 branches, 65,536 raw points and 65,536 resampled open-chain points; closed branches are not needlessly resampled.

`image-tip-evidence-cache.ts` avoids repeating a pure source measurement across equivalent calibrations. A weak RGBA-object key is combined with image dimensions, open/closed state and exact ordered native coordinates, including signed zero. It neither rotates a tracing start nor changes a sampling phase. Every observed pixel, including alpha reads that reject a proposal, is rechecked byte for byte before reuse. Unread pixels do not invalidate that measurement. Cloned results isolate callers; an open endpoint receives the current caller's fields, so cached data cannot retain an old node ID. Each image has at most eight entries and a two-MiB accounting budget. Pixel tracking and result storage can decline caching without changing the computed result. The cache requires a pure callback that reports all reads and returns acyclic plain data.

These mechanisms are implemented, but unresolved real JPEG regions have not received complete visual acceptance. Analytic tip, flat-end, rounded-end and shared-network tests remain independent gates; rejection of an unreliable proposal does not count as satisfying its intended-geometry assertion. The real JPEG overlays remain diagnostic evidence rather than proof of a unique physical fabric boundary. Verification results, skipped private-fixture cases and remaining failures belong in the current test report, not in this design document as a blanket pass claim.

`contour-independent-acceptance.test.ts` additionally exercises the complete default import against analytic ground truth, including hard and antialiased diagonals, faint paint, deterministic RGB texture, real corners, holes, ownership, gaps and overlap. `material-step-preservation.test.ts` separates pale material steps from diffuse illumination and isolated noise. Set `FPCAD_EDGE_AUDIT=1` when running `original-edge-real-audit.test.ts` to save original-image overlays and source fingerprints under `test-results/latest-edge/`.
